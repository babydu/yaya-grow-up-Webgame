# 慢慢长大

温柔视觉与真实时间成本相结合的浏览器养成小游戏。首次从小猫橘汐、小狗麦芽、宝宝阿团、小植物团子四个对象中选择一个并为它起名（最多 12 字，留空沿用默认名），名字贯穿界面、引擎日志与养育日记，持续照护与成长。

## 启动
```bash
python3 -m http.server 8000 --directory /workspace
```

入口为 index.html；规则引擎为 engine.js；界面逻辑为 game.js；插画为 visuals.js；背景音乐为 audio.js（Web Audio 本地合成音景，零外部音频文件）；样式为 style.css 与 enhancements.css。运行应用无需安装依赖。

美术资产位于 assets/：bg-{type}.jpg 为四间手绘房间背景，stages/{type}-{1..4}.png 为阶段抠图立绘，acc/{type}-{n}.png 为饰物抠图；来源为设计工具导出的角色设定集，重生成管线见 tools/prepare_assets.py（rembg 抠图 + 缩放，需在解压设计包后运行）。

存档保存在当前浏览器 localStorage（v2 含 worn `{ wear, place }` 双槽饰物与 health/status/criticalAt/leftAt 健康字段），支持第一版迁移、导出和导入。主页问候、天气行与房间滤镜按本机当地小时分清晨 / 正午 / 午后 / 傍晚 / 夜里五段，不请求外部天气。提醒仅在应用内生效。照护保持页面可见即可计时，切后台暂停；成长使用现实 1 天对应游戏 30 天的压缩日历。养育节奏（设置页：紧致 / 正常 / 宽松，默认正常）只缩放四项照护的关注间隔与需求下降速度，单次照护时长不变；紧致为正常的 0.75 倍，宽松为正常的 1.5 倍。正常档四项间隔约 3–6 小时（喂养按阶段 3/4/5/6，清洁宝宝 4.5、其余 5，心情 3.5，精力 4）。夜间节奏（默认开启，22 点至次日 6 点，设置页可调整或关闭）：就寝时段内需求衰减与健康度流失按半速结算，病危 24 小时宽限倒计时同步减半（实际可延长至约 32–40 小时），照护动作、任务计时、恢复速率（全需求 ≥30 时 +1/h）与成长经验照常。清洁类照护（换尿裤、铲猫砂、换尿垫、擦叶）一次只用一份，小铺按基础 / 舒适 / 优质三档拉开单次洁净度（+35 / +45 / +55，价格 8 / 10 / 16）；既有 `{type}-clean` 为舒适档。喂养一餐最多两份，营养组合与玩具固定一份。植物浇水免费、只补水分；第四项为施肥，消耗花肥或营养组合并主要恢复养分。日常花肥养分 +45，优质花肥养分 +55。照护弹窗内展示本次预计恢复量（含需求封顶提示）。档位差为游戏模拟，现实照护请咨询专业人士。领养页写明四种角色的互动节奏：小猫、小狗、宝宝会偶尔弹出 10 秒短时小事件（点到亲密度 +2，错过 −1，间隔 10–25 分钟随机），照护弹窗打开时推迟；小植物为安静养成，不弹短时事件。领养时可为角色起名（最多 12 字，留空沿用默认名），名字贯穿界面、引擎日志与养育日记。打开照护弹窗即按当前角色与动作分类主动展示一条养护小知识（喂养对应营养、换尿裤对应清洁），完成弹窗沿用同一条；相邻两次轮换不重复，展开即记入养育课堂已读。侧边导航「养育课堂」：仅展示当前养育角色的 24 篇通用养护科普（按喂养营养 / 清洁护理 / 情感陪伴 / 健康与观察分组），点卡片展开阅读并持久化已读进度，附「请咨询专业人士」免责说明；内容全部本地静态，无外部请求。主页健康工具箱：持有医疗用品或角色虚弱时显示，可直接使用医疗用品，无货时一键跳转小铺医疗页签。生活小铺含 16 件随身饰物（积分兑换、按阶段解锁、可穿戴）与医疗照护类商品（安心药箱、回春灵药）。侧边导航「我的背包」：小铺购得的商品统一收纳于此并在背包内使用——照护物资一键打开对应照护弹窗、医疗品按门控直接使用（数量随之扣减）、随身饰物分穿戴槽与摆放槽，可同时一件戴在身上、一件放在小屋（非消耗，收起自动收回背包，库存不变）；背包为空时提供前往小铺的引导入口。生活小铺回归纯购买入口：已拥有的医疗品与饰物展示「去背包使用 / 去背包」链接。饰物穿戴位置按物品形态逐件定义（visuals.js WEAR_POS）：植物叶纹陶盆底部对齐替换默认花盆，洒水壶 / 标签牌 / 园艺小铲摆放在盆边地面，猫狗围巾项圈头巾对准颈位，宝宝帽子居顶、围兜胸前、学步鞋底部对齐，玩具类（毛线球、拉绳球、木球、鱼坠、牙胶）落在角色身旁地面。

健康系统：需求长期低于 10 时健康度按每项 -0.75/真实小时流失（上限 3/h），全部需求 ≥30 时 +1/h 回复，每次有效照护 +2；分级为萎靡（<70）、生病（<40，成长经验减半、房间生病角标）、病重（<20，禁触摸与玩耍、主页出现虚弱风险横幅）。亲密度随时间缓慢流失（-0.1/h，夜间半速），一次有效照护 +2 大约补回一天的距离；需求触底时额外每项 -0.25/h（上限 0.8/h），进入病危再扣 8 点，病危期间额外 -0.6/h。回春灵药与药箱只恢复健康度，亲密度要靠之后的照护与触摸慢慢陪回来；已解锁的亲密度里程碑积分不收回。健康度归零进入 24 真实小时病危宽限期（横幅显示倒计时），可用回春灵药复活或经持续照护自然回升至 20 解除。回春灵药为强效医疗（恢复 60 健康度），健康度低于 70 的任何虚弱状态或病危窗口均可使用；安心药箱为轻度医疗（恢复 40 健康度），非病危且健康度低于 70 可用。病危期间喂养、清洁等照护动作全部封锁，只能用回春灵药挽回；照护完成时的需求恢复值按健康度线性系数 k=0.55+0.45×健康度/100 折算（健康度越高恢复越多，越低恢复越少，进行中的任务照常按结算时刻健康度折算）。睡眠系统：完成一次「安抚休息」（植物除外）后若精力仍未满，角色会安静入睡——睡眠期间喂养、清洁、玩耍、托管管家全部封锁（照护卡片置灰并显示「它在睡觉」，管家不计费），精力自动回复（白天 +6/h、夜间 +10/h），饱腹、洁净、心情仍按正常速度下降（睡着也会饿会尿，造成早起压力），健康度流失减半防「睡进病危」；精力回满自动醒来并记入日记，也可在睡眠横幅点「轻轻叫醒」手动唤醒（醒后即可喂饭换尿裤）。植物不适用睡眠系统（其精力项为施肥），精力已满时安抚不会入睡。睡眠封锁挂在睡眠状态而非时钟，白天午睡同样封锁、跨时区作息自洽。主页亲密度卡片下方有健康工具箱：持有医疗用品或角色虚弱时显示，可直接使用医疗用品（无需去小铺），无货时一键跳转小铺医疗页签。超时角色按类型叙事永久离开（baby 被家人接走 / cat·dog 出门远行 / plant 化作春泥），留念面板展示陪伴履历后可重新领养。旧 v2 存档自动补健康默认值。

## 积分与经济（Phase 0）
积分来源：初始 60；每日签到 11–17（连签加成）；有效照护每次 +5，每日上限 40；晋级 +20；亲密度里程碑（30/65）各 +10；另有「每日小任务」——完成一次照护、回应一次小心思、读一篇养育课堂各 +4，每日各一次（总 +12/天）。
保底机制「守夜求药」：当角色进入病危（健康归零的 24 小时窗口）、且没有回春灵药、积分又不足以兑换（灵药 60 分）时，可在病危横幅点「守夜求药」，安静守候约 2.5 分钟将积分补齐到 60（每日一次）。**守夜要求全程留在这一页**：切到别的标签、离开页面或关掉守夜窗，这一夜立即作废、进度清零，回到页面须从头守起（守夜中按钮显示「重新开始守夜」并提示「它还在等你」）——离开不能白嫖积分，陪伴才是唯一的药引。此保底只解决「因积分不足而失去伙伴」的最坏情形，不替代签到与照护；病危期照护全部封锁，仍须用灵药挽回。设计上生存永不依赖付费，后续变现走外观与广告加速（Phase 1+）。

## 版本
app.js 与 test.cjs 为保留的第一版实现，当前页面使用 v2 模块。新增方案位于 .monkeycode/specs/lifelike-care-v2/、ambient-bgm/、background-care/、bgm-now-playing/、design-pack-integration/、health-sickness-system/、realistic-care-quality/、plant-fertilize-nutrients/、care-pace/、short-moments/、backpack-accessory-fix/、care-knowledge/、custom-pet-name/、day-texture-dual-slots/、critical-lock-health-yield/、accessory-dye-variants/、moment-return-popup/、nanny-care/。

**贴心管家托管费（新增）**：开启托管后按真实时间扣积分，约 **10 分/小时**（`engine.js` 常量 `NANNY_RATE`）；托管完成的照护**不产生照护积分、不触发每日小任务**，库存不足仍按双倍价代购，积分不足以维持时会自动停止并提示。
物品价格（默认，可后台覆盖）：奶粉 20/5 份、主食 22–26/5 份、清洁 15/18/24 三档/5 份、营养组合 18/3 份、玩具 12/3 份；医疗（药箱 25、灵药 60）与饰物（30/45/60/80）暂不变。
平衡核算（以猫咪为例）：手动一天约 签到 14 + 照护 30（6 次）+ 小任务 12 = 56 收入，物资消耗约 **35–40**（奶粉+猫砂，单份约 3.6–5），净盈余约 **+15–20/天**（略高于消耗，去向外观等长期目标）；全程托管 24 小时需约 240 分且无照护积分、双倍代购，远超日常收入，会很快因积分不足自动停止，从而**引导亲自喂养**。
价格与托管费率支持后台配置：`data/site-config.json` 的 `prices` 覆盖表（按整包价格），后台「物品价格」可逐项修改并「恢复默认价格」，发布后全站生效。
紧急补足仅保留「守夜求药」：病危、无灵药、积分不足时开放（每日一次）；后续把付费 / 看广告作为最后兜底（未上线）。上述数值为可调参数（托管费率、任务奖励、照护上限）。

## 用户统计
匿名、无 Cookie 的一阶统计（页面时长、照护/领养/签到/晋级/托管/积分等聚合计数）由 `stats.js` 上报至 `server.js` 的 `POST /api/stat`，聚合在 `data/stats.json`；后台「统计与分析」可开关、查看累计与最近 7 天，并可配置 GA4（尊重 DNT / 需同意）。纯静态部署无统计接口。合规与指标取舍详见 `.monkeycode/docs/STATS.md`。

## 运营、广告与部署
全局运营配置存于 `data/site-config.json`（广告、公告、页脚），由前端 `site.js` 读取，**对所有访客生效**；访客本机仅保存「已关闭广告 / 已读公告」的个人状态。`admin.js` 提供**无可见按钮**的隐藏后台，入口 `#ops=<adminToken>`（token 在 `config.js`），可发布公告（顶部滚动条 / 进入弹窗）、管理广告、发布到服务器或导出 JSON。带后端时运行 `node server.js`（`PORT`/`OPS_TOKEN`）提供 `POST /api/site-config` 实时写入；纯静态部署用「导出 JSON」替换该文件。详见 `.monkeycode/docs/DEPLOY.md`。
