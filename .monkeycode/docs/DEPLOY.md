# 部署、全局配置与运营后台指南

面向项目所有者 / 运营者。玩法规则见 `INDEX.md`。

## 一、核心认知：配置分两层

| 层 | 存放 | 作用范围 | 说明 |
|---|---|---|---|
| 代码默认 + 密钥 | `config.js`（`window.SITE_CONFIG`） | 所有构建 | 默认值、`adminToken`（后台入口密钥） |
| **全局运营配置** | `data/site-config.json` | **所有访客** | 广告、公告、页脚、**物品价格覆盖**；后台「发布」写入此文件 |

前端 `site.js` 读取 `data/site-config.json`（带缓存穿透），因此**后台改的是全站配置，对所有访客生效**。访客本机 localStorage 只保存两类「个人状态」：已关闭的广告、已读的公告——不会影响他人。

## 二、两种发布方式（按部署形态选）

1. **带后端（推荐，可实时全站生效）**
   - 运行：`PORT=8080 OPS_TOKEN=你的密钥 node server.js`
   - `server.js` 同时提供静态站点与 `POST /api/site-config`（带 `x-admin-token` 校验），后台「发布到服务器」会原子写入 `data/site-config.json`，所有访客下次加载即生效。
   - 生产建议 Nginx/Caddy 反向代理到 `server.js`，开启 HTTPS。
2. **纯静态（无 Node）**
   - 直接上传整个目录到对象存储/CDN/Netlify/Vercel/GitHub Pages。
   - 后台点「导出 data/site-config.json」，用它替换站点里的同名文件后重新部署即可全站生效。

## 三、隐藏运营后台（无可见按钮）

- 入口：`https://你的域名/#ops=<adminToken>`（token 在 `config.js`）。无任何页面按钮，hash 不发往服务器、不被抓取。
- 面板能力：
  - 公告：标题/正文/链接，开关；展示方式可选「顶部滚动条」「进入弹窗」，可同时开启。发布自动提升公告版本，所有访客下次打开看到一次（可自行关闭）。
  - 广告位：顶部条幅 / 底部卡片开关；广告增删、上移下移、启用；一键模板（公告式条幅 / 赞助卡片）。
  - 站点：页脚补充说明。
  - 物品价格：按整包价格逐项修改（显示默认价与单份均价），「恢复默认价格」一键回到内置默认；发布后全站生效。价格覆盖存于 `prices` 字段，前端加载后应用到引擎（含购买、托管代购、界面显示）。
  - 发布：发布到服务器（全站）/ 本机预览 / 取消预览 / 导出 JSON / 清空为默认。
  - 高级：直接编辑原始 JSON 载入。
- 广告与公告均在**正常文档流**，绝不遮挡界面；每条广告带「广告」标签与关闭按钮，访客关闭后不再显示（可恢复）。
- 打开后台会自动关闭原生 `<dialog>`，避免顶层层遮挡导致无法点击。

## 四、快捷修改配置的其他方式（研判）

1. 隐藏后台 + 发布（带后端）或导出 JSON（静态）——日常首选。
2. 直接编辑 `data/site-config.json` 后重部署——纯文本改动最直接。
3. 控制台临时预览：`window.Site.preview({...})`（仅本机、不落盘）。
4. URL 调试参数（建议后续加）：如 `?noads=1`。
5. 构建期注入 / Headless CMS / 自建管理 API（规模化后）。

## 五、可继续增加的设置项（研判清单）

- 站点：标题/副标题、备案与联系方式、隐私/条款链接、SEO 关键词与 OG、主题色。
- 公告：定时上线/下线、只对首次访问者、分人群。
- 广告：多槽位（侧栏/详情）、到期时间、按设备/地区、频次与轮播、A/B、曝光/点击统计。
- 运营：活动/节日主题开关、维护模式、功能开关（管家/染色/课堂/短时事件）、版本更新提示。
- 玩法参数外置（谨慎）：签到区间、每日上限、病危宽限、夜间时段、节奏默认值、初始积分。建议只外置「运营可调参数」，一致性/存档校验相关常量仍留引擎。

## 六、升级与兼容

- 升级：替换部署目录即可（纯静态无迁移脚本；Node 方案重启进程）。
- 存档：玩家进度在其浏览器 localStorage，`engine.js` 的 `load()` 对旧字段做默认值兼容。
- 全局配置：`data/site-config.json` 与代码解耦，升级无需改动它；保留一份备份便于回滚。
- 缓存：`index.html`/`*.js`/`data/site-config.json` 建议 `no-store` 或带版本号；`assets/` 可长缓存。

## 七、安全说明

- `adminToken`（`config.js`）是「隐藏入口标识」，用于浏览器判断是否打开后台；它公开可见，**只做隐蔽、不是真正的鉴权**。
- 服务端写入由 `OPS_TOKEN` 校验 `POST /api/site-config` 的 `x-admin-token`：若服务器设置了 `OPS_TOKEN`（建议与 `adminToken` 不同、且足够随机），后台「运维写入密钥」需填入同一串；未设置 `OPS_TOKEN` 时回退用 `config.js` 的 `adminToken`（仅适合内网/临时）。
- 带后端时，只有持有 token 才能写入全局配置；不带 token 的写入返回 401。服务端拒绝越权、限制 body 大小、原子写入、屏蔽 `/server.js` 与点文件。
- 纯静态部署没有写接口，后台只能导出 JSON 由你替换文件——不存在被匿名篡改全局配置的入口。
- 不要把任何真实口令/第三方密钥放进 `config.js` 或 `data/site-config.json`；它们对访客可见。
