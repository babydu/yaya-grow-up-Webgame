# 部署、全局配置与运营后台指南

面向项目所有者 / 运营者。玩法规则见 `INDEX.md`。

## 一、核心认知：配置分两层

| 层 | 存放 | 作用范围 | 说明 |
|---|---|---|---|
| 代码默认 + 密钥 | `config.js`（`window.SITE_CONFIG`） | 所有构建 | 默认值、`adminToken`（后台入口密钥） |
| **全局运营配置** | `data/site-config.json` | **所有访客** | 广告、公告、页脚、**物品价格覆盖**；后台「发布」写入此文件 |

前端 `site.js` 读取 `data/site-config.json`（带缓存穿透），因此**后台改的是全站配置，对所有访客生效**。访客本机 localStorage 只保存两类「个人状态」：已关闭的广告、已读的公告——不会影响他人。

## 二、首次部署：设置写入密钥（引导）

后台有两个密钥，职责不同：

| 密钥 | 位置 | 作用 | 是否保密 |
|---|---|---|---|
| 入口 token | `config.js` 的 `adminToken`（URL `#ops=<token>` 打开面板） | 隐藏后台入口 | **不保密**：`config.js` 会发给每个访客 |
| 写入密钥 `OPS_TOKEN` | 服务器环境变量 | 校验「发布到服务器」与「查看统计/在线人数」 | **保密**：只有服务器知道 |

> 关键点：入口 token 对所有访客可见，泄露了它最多让人「看到」面板；**真正保护发布与统计的是 `OPS_TOKEN`**。不设置 `OPS_TOKEN` 时，写入校验回退到公开的 `adminToken`，等于任何人都能改全站公告/广告/价格。

**三步完成加固：**

```bash
# 1) 生成一个随机密钥（服务端命令，直接输出可用串）
node server.js --print-token

# 2) 用它启动（生产建议写进 systemd/PM2/.env，不要明文留在历史命令里）
OPS_TOKEN=<上一步的串> PORT=8765 node server.js

# 3) 打开后台 https://你的域名/#ops=<adminToken>，在「运维写入密钥」填入同一串，
#    点一次「发布到服务器」验证；统计与在线人数也会自动切到该密钥。
```

辅助提示：
- 启动时若未设置 `OPS_TOKEN`，服务端会在日志里打印上面的引导步骤；后台面板顶部「部署安全」也会持续显示黄色告警，设置完成后变为绿色「已受 OPS_TOKEN 保护」（可点「设置好了，重新检测」刷新状态）。
- 只想换一个不那么显眼的入口标识：把部署后 `config.js` 里的 `adminToken` 改成任意串（注意它仍对访客可见，别当密钥用）。
- 纯静态部署没有后端，不存在写入接口，跳过本节即可。

## 三、两种发布方式（按部署形态选）

**推荐先用 Docker（见第三节 A），一条命令部署、一条命令升级。**

> Docker 用户：`deploy.sh` 已自动生成并注入 `OPS_TOKEN`，本节可跳过；
> 本节面向直接运行 `node server.js`（无 Docker）的部署形态。

### A. Docker / 1Panel（最省事）

```bash
# 国内服务器一键安装（自动探测代理/GitHub 镜像加速 clone）
bash <(curl -fsSL https://ghfast.top/https://raw.githubusercontent.com/babydu/yaya-grow-up-Webgame/main/install.sh)

# 或者手动克隆再部署
git clone https://github.com/babydu/yaya-grow-up-Webgame.git
cd yaya-grow-up-Webgame
./deploy.sh      # 首次部署，自动生成 OPS_TOKEN
./upgrade.sh     # 之后每次升级
```

- `deploy.sh` 自动生成 `.env`（含随机 `OPS_TOKEN`），构建并启动容器。
- `upgrade.sh` 备份 `data/` → `git pull` → 重建容器，运行数据零丢失。
- 国内网络加速（`lib-network.sh`）：按优先级自动探测环境变量代理 → 本地常见代理端口（Clash/V2Ray 等）→ GitHub 镜像 → 直连；基础镜像依次尝试 Docker 加速源（daocloud/1Panel 等）后打回原名。全部失败回退直连。手动覆盖：`.env` 里设 `PROXY=`、`GITHUB_MIRROR=`、`DOCKER_MIRROR=`，或 `NO_MIRROR=1` 强制直连。

- `deploy.sh` 自动生成 `.env`（含随机 `OPS_TOKEN`），构建并启动容器。
- `upgrade.sh` 备份 `data/` → `git pull` → 重建容器，运行数据零丢失。
- 容器零 npm 依赖，`server.js` 仅用 Node 内置模块，镜像秒级构建。
- `data/` 以卷挂载持久化：统计、全局配置、广告/公告/价格覆盖都不丢。
- 1Panel 收尾：网站反向代理到 `http://127.0.0.1:8765` + 一键申请 HTTPS 证书（PWA 离线与安装需要 HTTPS）。
- 修改端口：默认对外端口 **8765**（避开 8080 等常用端口），改 `.env` 的 `PORT` 后重跑 `./deploy.sh`，同步更新反向代理目标。
- 资源占用（实测）：镜像拉取约 50 MB、运行时磁盘约 190 MB、空闲内存 22 MB、空闲 CPU 0%；`mem_limit: 256m` 做膨胀保险，1 核 1G 服务器即可。

### B. 直接运行 Node 进程

1. **带后端（推荐，可实时全站生效）**
   - 运行：`PORT=8765 OPS_TOKEN=你的密钥 node server.js`
   - `server.js` 同时提供静态站点与 `POST /api/site-config`（带 `x-admin-token` 校验），后台「发布到服务器」会原子写入 `data/site-config.json`，所有访客下次加载即生效。
   - 生产建议 Nginx/Caddy 反向代理到 `server.js`，开启 HTTPS。
2. **纯静态（无 Node）**
   - 直接上传整个目录到对象存储/CDN/Netlify/Vercel/GitHub Pages。
   - 后台点「导出 data/site-config.json」，用它替换站点里的同名文件后重新部署即可全站生效。

## 四、隐藏运营后台（无可见按钮）

- 入口：`https://你的域名/#ops=<adminToken>`（token 在 `config.js`）。无任何页面按钮，hash 不发往服务器、不被抓取。
- 面板能力：
  - 公告：标题/正文/链接，开关；展示方式可选「顶部滚动条」「进入弹窗」，可同时开启。发布自动提升公告版本，所有访客下次打开看到一次（可自行关闭）。
  - 广告位：顶部条幅 / 底部卡片开关；广告增删、上移下移、启用；一键模板（公告式条幅 / 赞助卡片）。
  - 站点：页脚补充说明。
  - 物品价格：按整包价格逐项修改（显示默认价与单份均价），「恢复默认价格」一键回到内置默认；发布后全站生效。价格覆盖存于 `prices` 字段，前端加载后应用到引擎（含购买、托管代购、界面显示）。
  - 发布：发布到服务器（全站）/ 本机预览 / 取消预览 / 导出 JSON / 清空为默认。
  - 高级：直接编辑原始 JSON 载入。
- 广告与公告均在**正常文档流**，绝不遮挡界面；每条广告带「广告」标签与关闭按钮，访客关闭后不再显示（可恢复）。
- 打开后台会自动关闭原生 `<dialog>`，避免顶层层遮挡导致无法点击。

## 五、快捷修改配置的其他方式（研判）

1. 隐藏后台 + 发布（带后端）或导出 JSON（静态）——日常首选。
2. 直接编辑 `data/site-config.json` 后重部署——纯文本改动最直接。
3. 控制台临时预览：`window.Site.preview({...})`（仅本机、不落盘）。
4. URL 调试参数（建议后续加）：如 `?noads=1`。
5. 构建期注入 / Headless CMS / 自建管理 API（规模化后）。

## 统计与分析（可选）

- 匿名统计（默认开启、可后台关闭）：`stats.js` 上报页面浏览、会话、可见时长、照护/领养/签到/晋级/托管/积分等聚合计数；`server.js` 的 `POST /api/stat` 白名单+钳制+限流，聚合到 `data/stats.json`。
- 后台「统计与分析 → 查看统计」：需管理员 token，读取 `GET /api/stats`，展示累计与最近 7 天。纯静态部署无此接口。
- 实时在线/活跃：`stats.js` 用本页内存临时 `presenceId` 心跳（不落盘），服务端内存维护最近 60 秒在线数；`GET /api/presence`（管理员 token）返回 `activeNow`/`onlineNow`/`activeToday`，后台打开时自动加载并每 30 秒刷新。服务重启或跨零点重置。
- 第三方统计：后台可填 GA4 测量 ID，并可选择「尊重 DNT」「需访客同意后加载」；需同意时出现底部同意条。合规要点见 `STATS.md`。
- 隐私：不使用 Cookie/持久设备标识，不采集个人信息；明细仅保留最近 60 天。
- 图表：后台「查看统计」含活跃时长折线、24 小时柱状、照护/领养/阶段分布等（纯 SVG，无外部依赖）。

## 后台全屏与内容安全
- 打开后台（`#ops=<token>`）时整页切换为后台界面，遮挡游戏、锁定滚动，避免误操作前台。
- 广告文案与公告正文支持**简单 HTML**（b/i/strong/em/a/br/p/ul/ol/li/small）。服务端存储前与前端渲染时都会用白名单净化：去除 script/style、事件属性、`javascript:` 链接等；`a` 仅允许 http(s) 或 `/` 链接。

## 部署形态研判：是否只保留后端版本
- **推荐：以后端版本（`node server.js`）作为唯一官方部署形态。** 后台发布、统计、价格即时生效都依赖它；纯静态只能改文件、无统计与实时发布。
- **不建议删除静态兼容代码**：`site.js` 在没有 `/api/stat` 时会静默降级，静态部署仍可玩（无统计/无实时发布）。保留兼容成本极低，且为 CDN/离线/预览提供退路。
- 若确需"只留后端"，做法是：部署一律 `node server.js`（或反向代理到它），并在文档中不再提供纯静态发布路径；无需大改前端（可选移除 `data/site-config.json` 的静态读取，改为仅 `GET /api/site-config`）。
- 结论：**部署口径以后端版本为准，代码保留静态降级**，兼顾统一运营与健壮性。

## 六、可继续增加的设置项（研判清单）

- 站点：标题/副标题、备案与联系方式、隐私/条款链接、SEO 关键词与 OG、主题色。
- 公告：定时上线/下线、只对首次访问者、分人群。
- 广告：多槽位（侧栏/详情）、到期时间、按设备/地区、频次与轮播、A/B、曝光/点击统计。
- 运营：活动/节日主题开关、维护模式、功能开关（管家/染色/课堂/短时事件）、版本更新提示。
- 玩法参数外置（谨慎）：签到区间、每日上限、病危宽限、夜间时段、节奏默认值、初始积分。建议只外置「运营可调参数」，一致性/存档校验相关常量仍留引擎。

## 七、升级与兼容

- 升级：替换部署目录即可（纯静态无迁移脚本；Node 方案重启进程）。
- 存档：玩家进度在其浏览器 localStorage，`engine.js` 的 `load()` 对旧字段做默认值兼容。
- 全局配置：`data/site-config.json` 与代码解耦，升级无需改动它；保留一份备份便于回滚。
- 缓存：`index.html`/`*.js`/`data/site-config.json` 建议 `no-store` 或带版本号；`assets/` 可长缓存。

## 八、安全说明

- `adminToken`（`config.js`）是「隐藏入口标识」，用于浏览器判断是否打开后台；它公开可见，**只做隐蔽、不是真正的鉴权**。
- 服务端写入由 `OPS_TOKEN` 校验 `POST /api/site-config` 的 `x-admin-token`：若服务器设置了 `OPS_TOKEN`（建议与 `adminToken` 不同、且足够随机），后台「运维写入密钥」需填入同一串；未设置 `OPS_TOKEN` 时回退用 `config.js` 的 `adminToken`（仅适合内网/临时，后台会显示黄色告警）。
- 带后端时，只有持有 token 才能写入全局配置；不带 token 的写入返回 401。服务端拒绝越权、限制 body 大小、原子写入、屏蔽 `/server.js`、点文件与 `data/*.tmp`，并对配置写入做限流。
- **统计数据不落静态目录**：`data/stats.json` 仅能通过带 token 的 `/api/stats`（或 `/api/presence`）读取，直接访问该文件返回 404，防止绕过鉴权批量抓取分析数据。
- `GET /api/ops-status`（带 token）返回写入密钥是否真正受 `OPS_TOKEN` 保护，供面板「部署安全」横幅做引导式判断。
- 纯静态部署没有写接口，后台只能导出 JSON 由你替换文件——不存在被匿名篡改全局配置的入口。
- 不要把任何真实口令/第三方密钥放进 `config.js` 或 `data/site-config.json`；它们对访客可见。
