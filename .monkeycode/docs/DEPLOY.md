# 部署、配置与运营后台指南

本页面向「项目所有者 / 运营者」，说明如何把《慢慢长大》部署到自己的服务器、如何快速改设置、以及隐藏后台的使用与安全边界。面向玩法逻辑的说明见 `INDEX.md`。

## 一、产物形态

纯静态站点：`index.html` + 若干 `.js/.css` + `assets/`，**无需 npm 依赖、无需构建**。把整个仓库目录上传到任意静态托管即可运行。

## 二、部署选项（任选其一）

- 自己服务器：Nginx / Caddy / Apache，root 指向站点目录，启用 HTTPS。
- 对象存储 + CDN：把目录作为静态资源上传（如 OSS/COS/S3 + CDN）。
- 平台托管：Netlify / Vercel / Cloudflare Pages / GitHub Pages（直接连仓库自动发布）。

缓存建议：
- `assets/`、`assets/stages/*`、`icon-*`：长缓存（内容不变，文件名可用版本号）。
- `index.html`、`config.js`、`*.js`：短缓存或不缓存（或加 `?v=时间戳`），确保改配置/升级后即时生效。

## 三、配置分层（关键认知）

| 层 | 存放 | 作用范围 | 用途 |
|---|---|---|---|
| `config.js` → `window.SITE_CONFIG` | 站点文件 | **所有访客** | 全局配置：广告、公告、页脚、SEO、adminToken |
| `localStorage`：`slow-growing-site` | 访客浏览器 | 仅当前浏览器 | 运营后台「本地预览」，或单个访客的个人偏好 |
| `localStorage`：`slow-growing-ad-dismissed` | 访客浏览器 | 仅当前浏览器 | 访客关闭某条广告的记忆 |

生效顺序：内置默认 ← `config.js` ← `localStorage` 覆盖。因此后台面板改了只影响自己浏览器；**要让所有访客看到，必须把配置写进 `config.js` 并重新部署**。

## 四、隐藏运营后台（无可见按钮）

- 入口：`https://你的域名/#ops=<adminToken>`，token 在 `config.js` 的 `adminToken`（默认 `mkx7d2`，请改成你自己的随机串）。
- 页面任何地方都不渲染进入按钮；hash 不会发给服务器、也不会被爬虫索引。
- 面板可做：广告位开关、增删改广告（顶部条幅 / 底部卡片）、页脚补充文案、查看/编辑 JSON、恢复被关闭的广告、重置本地覆盖。
- **发布全局变更的标准流程**：面板里调好 → 点「导出 config.js」→ 用它覆盖服务器上的 `config.js` → 重新部署（或直接替换该文件）。
- 打开后台时若领养弹窗等原生 `<dialog>` 正开着，会自动关闭它以免顶层遮挡。
- 退出：面板右上「关闭」，或按 `Esc`，或去掉地址栏 hash。

## 五、广告位约束（已实现）

- 顶部条幅（页头下方细条）与底部卡片（页脚上方）都处于**正常文档流**，不 fixed/absolute，不遮挡任何控件。
- 每条广告带「广告」标签与关闭按钮；访客关闭后本机不再显示对应广告（`clearDismissed` 可全量恢复）。
- 默认 `ads.items` 为空，线上默认无广告，避免误上线。

## 六、快速修改设置的其他方式（研判结论）

1. **隐藏后台 + 导出 config.js**（推荐日常）：可视化编辑，导出后替换文件，全程无构建。
2. **直接编辑 config.js 后重部署**：改全局配置最直接，适合纯文本/公告。
3. **浏览器控制台临时注入**：`window.Site.save({...})` 仅本机预览，适合调试。
4. **URL 查询参数临时调试**（建议后续加）：如 `?noads=1`、`?theme=dark`，便于分享排障链接。
5. **构建期注入（引入构建时）**：如把配置放 `VITE_SITE_CONFIG`/JSON，打包时注入；当前无构建，暂不需要。
6. **Git CMS / 轻后端（规模化后）**：配置放仓库、用 Headless CMS 或自建管理 API 编辑并触发自动部署。

## 七、可继续增加的设置项（研判清单）

站点级：标题/副标题、全站公告、页脚文案与备案号、联系方式、隐私/条款链接、SEO 关键词与 OG 图、favicon/主题色。

广告级：多槽位（顶/底/侧栏/详情）、到期时间、按设备或地区、轮播与频次、A/B、点击/曝光统计、赞助位样式模板。

运营级：活动开关（节日主题）、维护模式、功能开关（管家/染色/课堂/短时事件）、版本更新公告条。

玩法参数化（可逐步外置到 config.js）：签到积分区间、照护每日上限、病危宽限时长、夜间时段与半速、节奏默认值、初始积分。**建议**：把「可调运营参数」外置，涉及一致性/存档校验的常量仍留在引擎，降低误配风险。

合规：广告/隐私同意提示（欧盟等地区）、未成年人保护提示。

## 八、升级流程与兼容

- 升级：`git pull`（或上传新文件）覆盖部署即可，静态无迁移脚本。
- 存档：玩家进度在各自浏览器 `localStorage`；`engine.js` 的 `load()` 已对旧版本字段做兼容与默认值补全（如 `daily.tasks`、`vigil`）。升级后旧档可继续玩。
- 版本提示：可在 `config.js` 增加 `site.version` 与公告文案，配合顶部条幅提示「已更新」。
- 回滚：静态站点保留上一版目录即可秒级回滚。

## 九、安全说明（重要）

- hash token 属于「隐藏」而非「鉴权」，任何人读到 `config.js` 都能看到 token。但由于面板只写**本机 localStorage**，他人打开也只会改到自己浏览器，无法影响其他访客或篡改全局。
- 真正需要「多人协作的全局后台」时，应引入**服务端**：一个受保护的 `POST /api/config`（带登录/鉴权）写 `config.js` 或数据库，前端读取该接口；同时把广告/公告改为服务端下发。这是后续 Phase。当前静态方案对「单站点所有者」已足够。
- 不要把任何真实密钥/口令放进 `config.js` 或仓库；`adminToken` 只是入口标识。
